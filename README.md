# EmailBuilderDemo: Демонстрация паттерна Builder (C#)

Учебный проект на C#, показывающий применение паттерна проектирования **Builder (Строитель / Конструктор)** на примере сборки электронного письма.

Проект специально упрощён до учебной демонстрации: здесь нет полноценной бизнес-логики, а есть только сценарии, которые показывают сам принцип работы паттерна.

Идея: объект письма (`EmailMessage`) имеет много необязательных параметров (`Cc`/`Bcc`, HTML- или текстовое тело, заголовки, вложения), поэтому удобнее собирать его пошагово через билдер, а не через большой конструктор.

## Что показывает пример

- Сборку **сложного объекта** по шагам через цепочку вызовов.
- Валидацию обязательных полей **в момент `Build()`**.
- Повторное использование билдера через `Reset()`.
- Дополнительный слой **Director** (`EmailDirector`) для «типовых» писем.

## Где и почему здесь нужен паттерн Builder

`EmailMessage` — это пример объекта, который неудобно создавать через конструктор, потому что у него:

- есть **обязательные** части (`From`, минимум один `To`, `Subject`, тело письма),
- и много **необязательных** (Cc/Bcc, заголовки, вложения, HTML/текстовая версия).

Паттерн Builder решает это так:

- конфигурирование идёт **пошагово** через методы (`From(...)`, `To(...)`, `Subject(...)`, ...),
- результат создаётся **один раз** вызовом `Build()`,
- проверка корректности выполняется централизованно в `Build()`.

Дополнительно:

- `Reset()` позволяет **переиспользовать** один и тот же экземпляр билдера для нескольких писем,
- `EmailDirector` показывает, как можно вынести «типовые сценарии» в отдельный класс, чтобы не повторять одинаковые цепочки вызовов.

## Структура

- `Program.cs`
  - точка входа в приложение.
- `Application/EmailApplication.cs`
  - объединяет пользовательский сценарий, учебные примеры и вывод в консоль.
- `Builders/EmailBuilder.cs`
  - содержит интерфейс билдера и его реализацию.
- `Directors/EmailDirector.cs`
  - хранит готовые шаблоны сборки.
- `Models/EmailModels.cs`
  - содержит модель письма и модель вложения.
- `EmailBuilderDemo.csproj`
  - файл проекта на `.NET 9`.

## Что теперь делает консольное приложение

После запуска программа показывает меню, в котором пользователь может:

1. собрать базовое письмо,
2. собрать письмо по готовому шаблону через `Director`,
3. собрать письмо с вложением,
4. завершить работу приложения.

Такой вариант лучше разделяет ответственность:

- `Program` только запускает приложение,
- `DemoApplication` управляет пользовательским сценарием,
- `EmailScenarioService` хранит учебные примеры,
- `ConsoleEmailOutput` отвечает только за вывод результата в консоль.

## Как используется паттерн Builder в программе

Письмо собирается примерно так:

1. Задаём отправителя `From(...)`
2. Добавляем получателей `To(...)` (и при необходимости `Cc(...)`, `Bcc(...)`)
3. Задаём тему `Subject(...)`
4. Указываем тело `TextBody(...)` или `HtmlBody(...)`
5. (Опционально) добавляем заголовки `Header(...)` и вложения `Attach(...)`
6. Получаем готовый объект вызовом `Build()`
